# QRC_single_time_series — Phased Implementation Plan

Status: v1, 2026-07-24. Derived from the master specification (33 sections), Fujii & Nakajima
(PR Applied 8, 024030, 2017; arXiv:1602.08159v2), Hamhoum et al. (arXiv:2510.13634v2), the
`qrc-project-playbook` and `quantum-reservoir-computing` skills (including
`implementation_gotchas.md`), and the `handoff` skill. Copy this file to
`QRC_single_time_series/IMPLEMENTATION_PHASES.md` in Phase 0; `PLAN.md` is derived from it.

Thirteen phases, strictly ordered by dependency. Every phase ends by writing
`QRC_single_time_series/handoffs/HANDOFF_P<k>.md` before the session closes — no exceptions.

## 0. Global conventions and invariants (bind on every phase)

**G1 — Layout and naming.** All work under `QRC_single_time_series/` per the spec tree, plus
`handoffs/` for phase handoff documents. Nothing outside this folder is touched. Figures are
regenerated by scripts only; every table number is printed by a script, never hand-written.

**G2 — Qubit-order contract (one place, one test).** In all NumPy/SciPy matrix code the
*injection qubit is the leftmost tensor factor* (index 0 in `np.kron` order), so re-injection
needs no permutation. Qiskit is little-endian; there is exactly ONE translation function
(`quantum/endianness.py`) that (a) maps logical index ↔ Qiskit wire and (b) reverses counts
keys. Anchor test (from implementation_gotchas): build |0⟩⟨0|⊗|1⟩⟨1|⊗|+⟩⟨+|, trace out site 1,
re-inject |+⟩⟨+| at site 1; assert norm diff = 0 and single-site ⟨Z⟩ = (+1, 0, 0). A second
anchor: X on Qiskit qubit 0, measure all → counts key has '1' in the expected position after
the single reversal.

**G3 — Alignment contract (one function).** `data/windows.py::align(features_by_k, y, horizon)`
is the only place that pairs feature rows with targets. Next-step convention: row built from
information available at step k pairs with target y_{k+1} (Hamhoum Eq. 7; FN NARMA convention).
Exactness test: STM task at τ_B = 0 with the debug post-injection sample (v = −1, where
⟨Z_inj⟩ = 1 − 2s_k exactly) must give capacity C(0) = 1.0 to machine precision. Any off-by-one
anywhere in assembly collapses this test.

**G4 — Config identity.** Every experiment is a frozen dataclass/YAML; its SHA-256 over
canonical JSON is the artifact key. Feature matrices are cached as
`results/features/X_<hash>.npy` (float32 on disk, float64 in solves; a test asserts the two
give NMSE within 1%). Seeds: `reservoir_seed` (couplings), `model_seed`, `sampling_seed`,
`noise_seed`, `transpiler_seed` — all logged per run (spec §31).

**G5 — No-future-access guard.** `evaluation/autonomous.py::rollout(model, warmup, n_steps, …)`
receives ONLY the history slice; the harness owns the full series. Enforcement test
(`test_autonomous_no_future_access.py`): run the same rollout twice, once with the true future
and once with the future replaced by garbage/NaN — outputs must be bit-identical.
Companion tests: `test_recursive_feedback.py` asserts input_{t+1} == prediction_t bitwise;
`test_rewind_predicted_window.py` carries a provenance mask alongside the rewind buffer and
asserts that after t_w autonomous steps no truth-after-T value remains.

**G6 — Preregistration block (`configs/preregistration.yaml`, frozen at end of Phase 0,
before any test-set contact).**
- Error thresholds ε ∈ {0.25, 0.5, 1.0} (normalised by σ_train), also converted to index units.
- Product reliability levels p ∈ {0.8, 0.9}.
- Clipping budget c_max = 0.2; boundary-dwell budget 30% of steps within 1% of a boundary.
- Failure-rule default thresholds (see Phase 4) — tunable on dev data only.
- Bootstrap: stationary/moving-block, block length ≈ decorrelation time of the series
  (first ACF zero-crossing or 1/e time; computed on train only).
- Shot grid {128, 256, 512, 1024, 2048, 4096, 8192}.
- Sweeps that must never be defaulted (playbook): J·τ log-spaced over ≥ 2 decades; input-gain
  (encoding range [s_lo, s_hi] ⊂ [0,1]) over ≥ 3 settings.
- Written success criterion for Gate 1, filled and locked in Phase 0, of the form
  "QRC beats persistence on CNRMSE at h = 1–3 on the untouched test span of <dataset> by ≥ <m>%."

**G7 — Honesty battery (from both skills; applies to every results table).**
Size-matched ESN at *equal feature count* (not equal qubit count); Haar-random reservoir
control (identical injection and readout, structureless fixed Haar unitary in place of
e^{−iHτ}); NMSE = 1.0 mean-predictor line on every NMSE axis; effective rank (participation
ratio of the feature covariance) reported next to nominal feature count; claims framed as
parity / parameter efficiency, never speed-up; hybrid-readout ablation (quantum ⊕ classical
lags vs quantum-only vs classical-only) wherever a quantum contribution is asserted; the
signal-to-noise ceiling check precedes any shot-noise study (Phase 8/10).

**G8 — Errata register (`IMPLEMENTATION_NOTES.md` §Errata; things the source texts get
wrong or ambiguous, each resolved by an in-repo audit, never silently).**
1. Hamhoum print Lorenz (a,b,c) = (10, 28, 3/8); standard chaotic Lorenz uses β = 8/3 and their
   quoted LLE ≈ 0.9 is the 8/3 figure. Integrate both; document which reproduces the claimed
   behaviour (spec §20.2).
2. Hamhoum's ENSO LLE 0.05–0.1 is quoted from an observational coastal-temperature study, not
   from their ODE. Never transfer it; compute λ for the actual integrated system.
3. Hamhoum's "ENSO" ODE is the Vallis (1986, Science 232, 243) box model (dimensional form).
   Audit signs/parameters against Vallis 1986/1988 before trusting Eq. 13.
4. FN Eq. 15 (trained observable) is written for V = 1 only; the V > 1 operator is the
   Heisenberg-spread sum Σ_{n,v} w_{nv} e^{iHvδt} Z_n e^{−iHvδt}. Implementation reads
   observables at t + (v+1)τ/V, v = 0..V−1 (resolves the paper's index off-by-one; NV signals).
5. FN NMSE (Eq. A1) normalises by Σ ȳ², not target variance — for NARMA10 the two differ by
   ~×400. Both conventions are computed and labelled everywhere (`metrics.py`).
6. Spec §13 heading "MACKAY–GLASS" → Mackey–Glass.
7. FN paper's ensemble (NMR) readout has no back-action; any per-shot protocol on the FN
   stateful trajectory is simulation-only emulation, never a hardware claim.

**G9 — Citation discipline.** No entry enters `references.bib` unless title+authors+venue were
verified against a live page in the implementing session (playbook hard rule). The starter set
verified for this plan is listed in §5. Run the `citation-audit` skill before the final report.

**G10 — Handoff convention (applies to every phase).** Before closing phase k, write
`QRC_single_time_series/handoffs/HANDOFF_P<k>.md` following the `handoff` skill, with one
declared deviation: the file lives in the repo (not the OS temp dir) so the next session finds
it. Required sections: (1) phase objective and status against exit criteria, with the actual
numbers achieved; (2) artifact paths and config hashes; (3) decisions and deviations from this
plan, with reasons; (4) open issues and known bugs; (5) exact entry instructions for phase k+1
(commands, configs, tests that must be green first); (6) suggested skills for the next session
(minimum: `quantum-reservoir-computing` + `qrc-project-playbook`; add `citation-audit` where a
document ships). Reference artifacts by path; do not duplicate their content. Redact secrets.

## 2. Phases

### Phase 0 — Repository/data audit, environment, scaffold, PLAN.md

**Goal.** Everything the spec's §6 first-deliverable list demands, minus physics: inspect the
repo and the three CSVs, pin the environment, create the folder scaffold, write `PLAN.md`, and
freeze the preregistration block.

**Build.**
- `scripts/inspect_repository.py`, `scripts/inspect_data.py` implementing spec §14 items 1–12;
  outputs `data/manifests/<name>.json` (checksum, target column, units, frequency, coverage,
  missing policy = MASK never silent interpolation, scaling policy, transform policy, source).
- Raw CSVs copied unmodified to `data/raw/`; every derived file into `data/processed/` with the
  manifest hash in its name.
- `pyproject.toml` + `requirements-lock.txt` pinning: numpy, scipy, pandas, statsmodels,
  matplotlib, qiskit (≥1.x line), qiskit-aer, pytest, pyyaml; optional extras: torch (LSTM/GRU),
  pennylane (QLSTM). Record exact versions in the lock file; `utils/resources.py` logs them per
  run.
- `Makefile` with one target per experiment group; the largest grids are *listed but not wired
  to `make all`* (spec §31).
- `PLAN.md` (spec §6 contents) derived from this document; `configs/preregistration.yaml`
  filled and locked (G6), including the written Gate-1 success criterion.

**Known real-world traps to check in the audit (do not assume schemas).**
Missing-value sentinels −99.9 / −999 / −9999; duplicate or irregular months; which index
variant each file actually is (ENSO: ONI vs Niño3.4 vs MEI — different smoothing and
climatology baselines; SOI: Troup-standardised vs NCEI-standardised differ by scale;
PDO: Mantua vs ERSSTv5-based differ after 2002); whether values are already anomalies. The
anomaly-vs-raw decision follows the playbook rule: climate targets are modelled as anomalies
relative to a training-years-only climatology; treat detrending/deseasonalisation as explicit
ablations (spec §14). Cross-check magnitude/sign of the ENSO series against the statsmodels
`elnino` dataset as a cheap sanity probe.

**Exit criteria.** Manifests exist and are checksummed; `PLAN.md` reviewed; preregistration
frozen; `pytest` runs (empty suite passes); nothing outside the project folder touched.

**Soundness review.** No mathematical risk. The one irreversible decision is the
train/dev/test chronology (final 20% untouched test; rolling-origin validation inside the
first 80%) — encode it in `data/loaders.py` so no later code can re-split.

**Handoff →** write `handoffs/HANDOFF_P0.md` per G10; must additionally record the resolved
identity of each index (which ENSO/PDO/SOI variant), the chosen anomaly convention, and the
frozen preregistration values.

### Phase 1 — Exact operator core and validation anchors

**Goal.** `quantum/pauli.py`, `tensor.py` helpers, `partial_trace.py`, `hamiltonians.py`,
`observables.py` — every component validated against a known exact answer *before* any
reservoir exists (playbook build order rule 1).

**Build.**
- Pauli products, local operator embedding at arbitrary site (G2 order), expectation values,
  partial trace via reshape/transpose, injection channel
  ρ → ρ_s ⊗ Tr_inj(ρ) with ρ_s = ½(I + 2√(s(1−s)) X + (1−2s) Z).
- FN Hamiltonian H = Σ_{i<j} J_ij X_i X_j + Σ_i h Z_i, J_ij ~ U[−J/2, J/2] drawn once per
  `reservoir_seed`; store seed, coupling matrix, fields, spectrum (spec §8.2).
- Exact evolution by eigendecomposition H = WΛW†; also `scipy.linalg.expm` path; equality test
  to 1e−12.
- Optional but cheap: level-spacing ⟨r⟩ diagnostic with the Atas anchors
  (Poisson 0.3863, GOE 0.5307), computed on the central 50% of the spectrum with
  near-degeneracies (gap < 1e−12) dropped — used later to certify "chaotic" configs.

**Tests** (`test_pauli.py`, `test_partial_trace.py`, `test_hamiltonian.py`,
`test_encoding.py`): the G2 re-injection anchor; ⟨Z_inj⟩ = 1 − 2s and ⟨X_inj⟩ = 2√(s(1−s))
after injection; ⟨Z_other⟩ untouched by injection (catches index errors, which are silent);
trace/Hermiticity/positivity (eigmin ≥ −1e−12) preserved by injection∘evolution; unitarity
of U; purity falls from 1 to a plateau under repeated injection.

**Exit criteria.** All anchors green at N ∈ {2, 3, 5}.

**Soundness review.** Standard; d ≤ 2^N with N ≤ 10 for anything dense (see §3 budget). The
injection channel is CPTP by construction (partial trace then tensor with a valid state), so
"do not represent the replacement as a unitary statevector transformation" (spec §8.3) is
satisfied structurally.

**Handoff →** `handoffs/HANDOFF_P1.md`; record the endianness contract test names and the ⟨r⟩
values for the default reservoir seeds.

### Phase 2 — Exact Fujii–Nakajima reservoir, features, readout, metrics, trivial baselines

**Goal.** The exact NumPy reference reservoir that defines the ceiling for everything else,
plus the whole feature→readout→metric chain, physics-free-testable.

**Build.**
- `quantum/exact_qrc.py`: generator `run(inputs, x0=None) → Iterator[(k, v, ρ)]`, sample v at
  t = kτ + (v+1)τ/V, v = 0..V−1 (G8-4). Debug flag exposes the post-injection instant (v = −1)
  for the G3 exactness test only. Efficient inner loop: with σ = W†ρW all V readouts at step k
  are one GEMM against a precomputed phase matrix Φ ∈ C^{V×d²}; advancing the state is one
  basis round trip ρ^{(V)} = W(σ⊙Φ_V)W†.
- Features x' = (1+⟨Z⟩)/2 plus bias; feature cache per G4. Observable set is a config field
  (`observables.py`: list of Pauli strings; fast path for the Z-family via diagonal + FWHT) so
  later ZZ extensions are config, not code.
- `models/readout.py`: centre X and y on train stats, solve without bias column, recover
  intercept; one economy SVD gives the whole ridge path w(λ) = V diag(s_j/(s_j²+λ)) Uᵀy and
  dof(λ); multi-target Y ∈ R^{L×T} in one decomposition; per-target λ; λ = 0 (pinv) path kept
  as the paper-faithful mode with ‖w‖₂ and retained rank logged; GCV-via-SVD selector for thin
  or regime-switching validation tails (playbook gotcha).
- `evaluation/metrics.py`: MSE/RMSE/MAE, BOTH NMSE conventions labelled (G8-5), R², Pearson,
  MASE, anomaly correlation; capacity C(τ_B) with the finite-length floor estimated as the
  MEAN over τ_B ∈ [450, 500] rather than the single τ_B = 500 point (cuts floor noise by √50);
  effective rank; NMSE(mean predictor) = 1.000 anchor.
- Trivial baselines now (they are part of metric definitions): climatological mean,
  persistence, seasonal persistence (lag-12 for monthly data), fit on train only.

**Tests** (`test_exact_qrc.py` + physics-free readout suite): synthetic Y = XW recovered
exactly at λ = 0; ridge endpoints (λ→0 matches lstsq; λ→∞ drives w→0, intercept→ȳ); batched
multi-target equals per-column; standardisation invariance of predictions at λ = 0; float32
cache vs float64 recompute within 1% NMSE; the G3 STM-τ_B=0 exactness test; white-noise
features vs a real target reproduce the analytic capacity floor ≈ τ_max/L_test.

**Design constraint to encode as an assert.** Feature count MV + 1 ≤ L/5 (FN's
overdetermination assumption): at L = 3000, M = N (Z-only) allows the paper grid; any
expanded-observable config must either lengthen L or cap V — refuse to run otherwise.

**Exit criteria.** Reproduce FN Fig. 5 qualitatively on one 5-qubit seed (C_STM rises with V,
saturates near V ≈ 10; C_PC(τ_B ≥ 1) ≈ 0 at V = 1) and NARMA sine-input Table-I ordering
(QR beats LR at every V; error falls with V). Order-of-magnitude agreement only — couplings
are random and the paper's pinv cutoff is unstated (G8), so exact matches are not a criterion.

**Soundness review.** The mandated sweeps (Jτ over ≥2 decades; input gain) are wired as
config axes now, not bolted on later. Effective rank is computed for every feature matrix from
this phase onward — under a scalar drive, nominal NV features typically expose far fewer
independent directions, and that number (not NV) is what the size-matched ESN must match (G7).

**Handoff →** `handoffs/HANDOFF_P2.md`; record the Fig.-5-style curves' file paths, the
measured effective ranks, and the exact feature-count/L budget table.

### Phase 3 — Trotterised matrix mirror + Qiskit implementations + validation ladder

**Goal.** Spec §§2.2, 2.3, 8.7, 10, 12: an exact-matrix Trotter model and ideal/noisy Qiskit
models that agree with it by construction, with every error source isolated.

**Build.**
- `quantum/schedule.py`: a `Schedule` dataclass — ordered list of (gate, sites, angle) for one
  evolution block — produced ONCE per config and consumed by BOTH
  `exact_trotter_qrc.py` (matrix products) and `qiskit_qrc.py` (circuit builder). Parity is
  then structural, not coincidental. Layouts: FC-TFI, NN-TFI, Opt-NN-TFI (Hamhoum Fig. 3/4
  orderings).
- Angle conventions pinned by a two-qubit unit test: matrix exp(−iJτ X⊗X) equals the RXX(2Jτ)
  unitary to 1e−12; likewise RZ(2hτ) vs exp(−ihτZ). This single test kills every factor-of-2
  bug class.
- Qiskit paths: (a) statevector for unitary-only validation circuits; (b) density_matrix
  method for reset-containing circuits (deterministic reference); (c) `save_expectation_value`
  / `save_density_matrix` at intermediate points for virtual nodes WITHOUT destructive
  measurement — documented as simulation-only (G8-7); (d) finite-shot sampling; (e) noisy
  simulation via `noise_models.py` (synthetic channels + stored backend snapshot;
  `scripts/export_backend_noise_model.py` freezes coupling map, basis gates, T1/T2, gate and
  readout errors, durations, layout — spec §11's "no live calibration" rule).
- Counts → ⟨Z_i⟩ = P(0) − P(1) through the single endianness function (G2);
  `test_count_to_expectation.py` uses X on one qubit → ⟨Z⟩ = −1.
- Shot emulation used consistently across ALL models for fair comparison (gotchas formula):
  z ∈ [−1,1], p = (1+z)/2, σ(z) = 2√(p(1−p)/S), emulate clip(z + ξσ(z), −1, 1), ξ~N(0,1),
  seeded per feature per step. This is the cheap path for shot studies on the FN track, where
  a literal per-shot hardware protocol does not exist (G8-7).

**Validation ladder tests (spec §12).**
L1 exact dense H-evolution vs L2 exact matrix Trotter: difference = Trotter error only; report
operator norm, state fidelity, feature error vs κ and τ. L2 vs L3 (Aer density matrix): agree
to atol 1e−10 (same Schedule ⇒ same unitaries). L3 vs statevector-trajectory average over M
stochastic-reset runs: |mean − exact| ≤ 3·SE, SE ~ 1/√M (`test_qiskit_parity.py`). L3 vs L4
finite shots: within binomial error. L4 vs L5 noisy: differences attributed to the injected
channels only.

**Exit criteria.** Ladder green at N ∈ {3, 5, 8} on both FN and rewind-style blocks; Trotter
error curves stored; a one-command `make validate-ladder`.

**Soundness review — the memory wall and its fix (this is the plan's most important
feasibility catch).** Dense density matrices cost 16·4^N bytes: N = 10 → 16 MB (fine),
N = 12 → 268 MB (borderline), N = 15 → 17 GB (infeasible). Therefore: (a) the FN *stateful*
track — which cannot be purified because each step adds a reset — is capped at N ≤ 10
(the paper uses ≤ 7; nothing is lost). (b) The rewind track re-initialises every window, and
its only nonunitary operations are the (t_w − 1)·d_inj injection resets inside one window —
these dilate exactly (Stinespring): give each reset a fresh ancilla prepared in |0⟩ and swap
instead of resetting. A single-channel window (d_inj = 1, t_w = 10) at N reservoir qubits is
then a PURE statevector on N + 9 qubits whose observables equal the density-matrix values
exactly: N = 12 → 21 qubits (32 MB), N = 15 → 24 qubits (268 MB) — feasible. Implement this
as `rewind_qrc.py`'s exact mode; keep Aer MPS as a cross-check for NN circuits. This unlocks
every Hamhoum configuration exactly, which the naive density-matrix route cannot do.

**Handoff →** `handoffs/HANDOFF_P3.md`; record achieved parity numbers per ladder level, the
Trotter-error table, pinned Qiskit/Aer versions, and the dilation-mode memory measurements.

### Phase 4 — Autonomous rollout engine, effective-horizon metrics, failure taxonomy

**Goal.** Spec §§16, 17, 19, 21 as a physics-free, fully unit-tested layer. Everything here is
testable with a toy AR(1) "model" before any quantum object exists — build it that way.

**Build.**
- `evaluation/autonomous.py::rollout(model, warmup, n_steps, domain_policy, telemetry)`.
  Model protocol: `warm(history) → state`, `step(state, u) → (state, ŷ)`. Two concrete
  adapters: stateful-FN (retain ρ across autonomous steps — spec §16.1, never reinitialise)
  and rewind-buffer (spec §16.2, provenance mask carried).
- Domain policies (spec §16.3), all telemetered, none silent: A hard clip; B smooth bounded
  map (e.g. u ← σ_logistic scaled to [s_lo, s_hi]); C terminate-on-violation; D alternative
  wider-domain encoding (input-gain remap). Telemetry: total clips, clip fraction, first clip
  time, pre-clip values, max violation, boundary dwell, excursion beyond train range.
- `evaluation/accumulated_error.py`: CNRMSE_T(h), CRMSE_T(h), CNMAE_T(h) with σ_train from
  train only.
- `evaluation/prediction_horizon.py`: H_error(T, ε) with the prefix-for-every-k rule (a
  trajectory cannot re-validate after failing); H_skill per baseline with the aggregated
  lower-CI-positive rule; H_reliable from the rule registry; H_effective = min(...), with all
  components reported (spec 17.6 "never only the minimum"); S_effective(h) survival;
  H_product(p).
- `evaluation/failure_modes.py`: registry with preregistered defaults (dev-tunable only):
  blow-up |x̂| > 1.5×train range; fixed point: rolling std < 0.05·σ_train over 24 steps; mean
  collapse: |x̂ − μ_train| < 0.1·σ_train over 24 steps; variance collapse/explosion:
  window var < 0.25× / > 4× train var; spurious limit cycle: dominant spectral peak > 60%
  power with periodic ACF; saturation: clip fraction > c_max or boundary dwell > 30%;
  stochastic instability: seed-to-seed divergence with deterministic core stable. Multiple
  labels allowed; first-failure time recorded.
- `evaluation/statistics.py`: stationary/moving-block bootstrap over origins (block per G6);
  Diebold–Mariano with Harvey small-sample correction per horizon; multiplicity noted.
- Multi-origin driver (spec §21): 20–50 origins, spacing ≥ one decorrelation time where the
  record allows.

**Tests.** The G5 trio (no-future mutation; feedback identity; window provenance) plus
`test_accumulated_error.py` on hand-computed error sequences,
`test_effective_prediction_time.py` on synthetic error curves with known H under each ε
(including a curve that dips back under ε after failing — must NOT re-validate),
`test_failure_classification.py` on constructed pathologies, `test_feedback_scaling.py`
(inverse-transform → rescale → encode round trip is the identity on in-range values).

**Exit criteria.** All of spec acceptance items 8–13 demonstrably green with the toy model.

**Soundness review.** H_error is well defined because CNRMSE is a running average and can dip
after a spike — the for-every-k clause is load-bearing; the test above pins it. Skill uses the
SAME rollout engine for every baseline (spec §24: no baseline sees the future). The
sanity identity NMSE(mean) = 1 anchors the CSkill sign convention.

**Handoff →** `handoffs/HANDOFF_P4.md`; record the frozen failure-rule thresholds and the toy
model's horizon table used as the regression fixture.

### Phase 5 — Mackey–Glass autonomous reproduction (GATE)

**Goal.** Spec §13. Nothing observational runs until this gate passes.

**Build.**
- `dynamical_systems/mackey_glass.py`: FN's exact discrete recipe (Euler step σ = 1/10,
  subsample ×10; α=0.2, β=10, γ=0.1; τ_MG ∈ {16, 17}); linear scale to [0,1]; long washout.
- Teacher forcing s_{k+1} = ȳ_k on 10 000 steps; close the loop for 2 000 (spec protocol);
  N ∈ {6, 7}, τΔ per FN Table II; uniform train-time reservoir-state noise in [−σ, σ] as a
  CONFIG, off by default.
- Outputs: trajectories, one-step error before closure, CNRMSE curves, H_error/H_effective,
  delay plots (y_k, y_{k+15}), power spectra, failure labels, λ̂ of the generated series by
  (a) FN's perturbation-pair method and (b) the ported scalar estimator (Rosenstein-type;
  reuse the existing implementation from the user's prior Lyapunov work).

**Also run here (cheapest place to settle it): the noise≡ridge question (spec §22.2).**
For feature noise uniform on [−σ, σ] i.i.d. per entry, E‖y − (X+E)w‖² = ‖y − Xw‖² +
L(σ²/3)‖w‖² under this repo's loss convention ⇒ expected equivalence λ_eff ≈ Lσ²/3. Verify
numerically over ~50 noise seeds; report the match AND the single-draw scatter. Input noise
(spec §22.3) is a different intervention (changes visited states) — implemented in
`training/input_noise.py`, compared separately.

**Exit criteria (the gate).** τ_MG = 16: closed-loop trajectory tracks the target over the
evaluation span with NMSE within an order of magnitude of FN Table II. τ_MG = 17: tracks for
O(100–300) steps, then diverges pointwise while the delay plot remains attractor-like and
λ̂_generated > 0 (FN report 0.0022–0.0071 per step in their units — same sign and order
suffices; couplings are random so exact values are not reproducible). Both estimators of λ̂
agree in sign and order. If the gate fails: debug ladder = anchors (P1) → alignment (G3) →
readout scale/λ (P2) → Schedule parity (P3), in that order, before touching hyperparameters.

**Soundness review.** Feasible by construction: N = 7 density matrix is 128×128; 12 000 steps
× V samples is minutes. FN's own MG protocol already demonstrates the target behaviour, so
this is a reproduction risk, not a feasibility risk. Clipping may fire even here — telemetry
on, and a run pinned at a boundary is classified saturation, not success.

**Handoff →** `handoffs/HANDOFF_P5.md`; must include the gate verdict with numbers, the
noise≡ridge regression coefficients, and (if the gate failed) the debug-ladder findings.

### Phase 6 — Rewind QRC (single channel) + learned-map Lyapunov machinery

**Goal.** Spec §9 adapted to one input channel, plus the delay-map analysis the spec §20.3
demands — this is the piece that turns "how long can it predict" into a computable dynamical
quantity.

**Build.**
- `quantum/rewind_qrc.py`: |+⟩^⊗N init, window t_w = 10 (sweepable), per-step injection reset,
  Ry(2 arcsin√u) encoding, NN-TFI / Opt-NN-TFI Schedule, first-order κ = 1, local Z readout
  (Hamhoum Algorithm 1). Exact mode = the Stinespring-dilated statevector from P3; Qiskit
  modes reuse P3 machinery. Memory qubits m ∈ {1,…,4} per injection qubit; h = 0.5;
  J ~ U[−0.5, 0.5]; τ ∈ {0.01, 0.1, 1, 10} as starting values only (spec: not assumed optima;
  G6 mandates the wider Jτ sweep).
- The learned maps: F: R^{t_w} → R (exact, noiseless ⇒ deterministic) and the delay map
  G(window) = shift ∘ append(F). `evaluation/lyapunov.py`: central finite-difference Jacobian
  of G (step ~1e−6·scale), Benettin QR product for the t_w-exponent spectrum; independent
  λ_max from the generated scalar series; comparison table Jacobian vs scalar vs true-system.
- Unit test: `test_rewind_predicted_window.py` (provenance) already exists from P4 — wire the
  real model through it.

**Exit criteria.** Rewind one-step MSE on the two synthetic MTS-reduced-to-univariate tasks is
in the plausible band relative to the trivial copy baseline (Hamhoum's copy baseline: 0.0067
ENSO-ODE / 0.017 Lorenz vs their model's 0.0036 / 0.0087 for the multivariate case — the
univariate adaptation only needs to beat copy, not match those numbers); Jacobian and scalar
λ̂ agree on a known map (validate the machinery on the logistic map, r = 3.9, λ = ln|…|
computed numerically, before pointing it at F).

**Soundness review.** Two traps, both handled by construction. (1) Determinism: F is a
deterministic map only in expectation-value mode; with shots it is a stochastic map and a
Lyapunov *spectrum* is undefined — shot runs report divergence rates, labelled as such
(spec 20.3 last line). (2) Differentiability: hard clip makes G non-smooth at the boundary;
Lyapunov runs therefore use domain policy C (terminate) or operate on verified-interior
trajectories; never differentiate through a clip. Pre-registered comparison (playbook
calibration prior): recurrent FN vs windowed rewind on the same series — expect recurrence to
be worth more than tuning (their ENSO-task calibration was ≈0.60 vs 0.75 NMSE); record whether
this replicates.

**Handoff →** `handoffs/HANDOFF_P6.md`; include the logistic-map validation numbers, the
F-map spectrum for the default config, and the FN-vs-rewind pre-registered comparison result.

### Phase 8 — Controlled-system campaign + dynamical audits

**Goal.** Spec §§5.1, 18.1, 20, 23 on Mackey–Glass, Lorenz-63, and the Vallis/Hamhoum ENSO
ODE, with every borrowed equation audited before use.

**Build — audits first (spec §20.2, G8-1..3).**
- `dynamical_systems/lorenz63.py`: integrate BOTH β = 8/3 and the printed 3/8 at (σ, ρ) =
  (10, 28); Benettin λ_max for each; document which reproduces the ~0.9 figure Hamhoum quote
  (expected: 8/3, λ ≈ 0.906 in standard time units — confirm in-run, do not trust this plan's
  memory either); select and record.
- `dynamical_systems/enso_ode.py`: the Vallis (1986) box model. Fetch the primary source in
  the implementing session; check Hamhoum Eq. 13 signs and parameters (B = 940, Δx = 7.5,
  C = 3, u* = −14.2, T̄ = 16, A = 1, T* = 28) against it; establish the time unit from the
  equations (so "steps" convert to physical time honestly, or report steps + LT only if the
  unit cannot be pinned); compute λ_max ourselves. Never reuse the 0.05–0.1 observational
  figure (G8-2).
- λ estimator cross-validation: Benettin (Jacobian) vs Rosenstein (scalar) on Lorenz;
  agreement within estimator error bars is a precondition for reporting any learned-map λ.

**Build — campaign.**
- 20–50 origins per system × {FN, rewind} × baseline battery; H_error/H_skill/H_reliable/
  H_effective distributions; horizons in steps AND Lyapunov times (never raw-step comparisons
  across systems — spec §20.1); dynamical-fidelity suite (spec §18.1): invariant measure,
  spectra, ACF, recurrence plots/quantification, correlation dimension where defensible,
  λ_generated vs λ_true.
- Shot-noise accumulation (spec §23) on Lorenz and MG: PRECONDITION — the signal-to-noise
  ceiling check (gotchas): measure the analytic (noiseless) ceiling first; if noisy error ≈
  analytic error and no ridge helps, the config has too little per-feature signal and the
  study would measure nothing — switch to a stronger-signal config before proceeding. Then:
  shot grid × seeds × origins; fit H_effective = a + b·ln S; compare b against the chaotic
  prediction b ≈ 1/(2 λ_max Δt) (perturbation δ₀ ∝ S^{−1/2} amplified at rate λ). Deviations
  are findings, attributed per spec §23's list (bias, clipping, non-Gaussian error, readout
  bias, finite memory) — never forced to agree.

**Exit criteria.** Audited equations documented with the decisive integrations attached;
horizon tables with CIs for all three systems; the H-vs-ln S curve with fitted slope and the
theoretical slope side by side.

**Soundness review.** The valid-time-in-Lyapunov-units convention is the field standard for
closed-loop RC on chaos (Jaeger–Haas 2004; Pathak et al. 2018 — verify live before citing) and
is what makes MG/Lorenz/Vallis numbers mutually interpretable. Expect H_effective of a few LT
for a well-tuned reservoir; an apparent 20-LT horizon is a leak until proven otherwise.

**Handoff →** `handoffs/HANDOFF_P8.md`; must include the β-audit verdict, the Vallis audit
verdict with the time-unit decision, λ tables, and the fitted shot-slope vs theory.

### Phase 10 — Shot budgets, noise models, and feature-space analysis

**Goal.** Spec §§11, 23 (observational leg), 27: what noise and finite sampling do to
features, readout, and horizon — including an honest adjudication of Hamhoum's
noise-as-regulariser observation.

**Build.**
- Noise grids on the rewind model (it is the hardware-shaped one): synthetic channels swept
  (readout p, depolarising 1q/2q, thermal relaxation with stored durations) and the frozen
  backend-snapshot model; shots per G6 grid; identical data/origins as P8/P9 subsets.
- `evaluation/diagnostics.py` feature-space suite (spec §27): bias/variance/RMSE/correlation
  vs exact features, covariance, cosine similarity, singular values, explained variance,
  effective rank (Rank_eff = 1/HHI, Hamhoum Eq. 17, computed on standardised features),
  condition number, readout-coefficient stability across seeds.
- The falsifiable form of the regulariser claim: if hardware-like noise improves test error
  only by conditioning the readout, then explicit ridge (or SVD truncation) tuned on dev at
  matched effective dof must recover at least the same gain WITHOUT the noise. Run
  noise-vs-ridge-vs-truncation as a three-arm comparison across seeds, origins, and folds;
  a "benefit of noise" is claimed only if it survives all three axes AND beats the matched
  classical regulariser (spec §27's persistence requirement, sharpened). SVD-truncation /
  filtering of noisy reservoir states à la Ahmed–Tennie–Magri (QMI 2025) is the implemented
  mitigation arm.
- Horizon-vs-shots and horizon-vs-noise-strength curves for the observational indices where
  budget allows (spec fig. 31–35).

**Exit criteria.** The three-arm adjudication table with CIs; feature-space dashboards for
simulator vs noisy per dataset; recommended operating shots per config.

**Soundness review.** The signal-to-noise ceiling check (P8) gates this phase too — a config
whose analytic ceiling already sits at the noisy error cannot support any noise conclusion.
Recursive amplification means open-loop feature RMSE understates closed-loop damage; the
horizon curves, not the feature RMSEs, are the decision-relevant output (spec §2's last
bullet).

**Handoff →** `handoffs/HANDOFF_P10.md`; include the adjudication verdict sentence ("noise

| Object | Size / cost | Verdict |
|---|---|---|

| Dense ρ, N = 10 | 1024², 16 MB; step ~ms | fine (FN cap) |
| Dense ρ, N = 12 | 4096², 268 MB; H eig once ~min | borderline; small runs only |
| Dense ρ, N = 15 | 32768², 17 GB | infeasible — never attempt |
| Rewind dilated statevector, N + (t_w−1)·d_inj | N=12→21q: 32 MB; N=15→24q: 268 MB | feasible; exact |
| FN MG run (N=7, V=10, 12k steps, exact) | minutes | gate is cheap |
| Rewind window circuit on Aer DM (12q, ~250 layers) | ~seconds each | 990 circuits ≈ tens of min |
| Full noisy grid (shots × noise × seeds × origins) | hours–day | configurable; never in `make all` |

Feature/solve costs are negligible next to state evolution once the P2 cache is in place; the
whole readout path is one SVD of an L × (MV+1) matrix per config.
