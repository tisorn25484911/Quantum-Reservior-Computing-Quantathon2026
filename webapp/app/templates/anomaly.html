Forecast-then-Detect

Run the reservoir forward on its own output to produce a multi-step trajectory, so that anomaly detectors could later be run on the forecast rather than on observed data — flagging an event before it happens, with warning time up to H.

Only the forecast half is built. This page runs the recursive rollout and measures how far its skill survives. The detection half (stochastic ensembles, matrix-profile / isolation-forest scorers, extreme-value thresholds, event debouncing) is not implemented, so no anomaly probability is shown. A probability from uncalibrated machinery would be the most misleading number this app could display.
xxz_hx has no disorder — seed affects only the ESN.
Why recursive rollout is the hard case. After the first step the reservoir is driven by its own prediction, not by data, so errors compound. The resulting skill-decay curve — not the one-step error — is what decides whether there is any usable warning time.
