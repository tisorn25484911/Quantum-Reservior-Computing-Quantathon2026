Reference · Method

Method, and what these numbers are allowed to claim

This page exists because a demo is the easiest place in a project to accidentally overclaim. Everything the app measures is written down here, including the parts that are unflattering.

What is actually being computed

A scalar time series is rescaled into [0, 1] and injected, one sample per step, into an exactly simulated quantum reservoir: a disordered, fully-connected transverse-field Ising system of n qubits. Each step re-prepares an input qubit and evolves the whole register under a fixed Hamiltonian, reading out ⟨Zi⟩ at several virtual nodes plus, optionally, the two-point ⟨ZiZj⟩ correlators. Those expectation values are the features; a ridge regression on top of them is the only trained part of the model.

The implementation is QRC_code_stack/stage1_numpy_core/qrc_core.py, which repository law R2 designates as the semantic definition for the whole programme. It is not a mock or a stand-in: this app drives the same propagator the handbook's numbers came from.

What this is not

  • Not quantum hardware. Every figure is classical simulation of a small quantum system, exact to machine precision.
  • Not a speed-up claim. At these sizes (n ≤ 8, so a state space of at most 256) there is no quantum advantage available to demonstrate, and none is asserted.
  • Not a product benchmark. One seed, one chronological split, one dataset per run. Differences of a few percent between methods are noise, and the app says so rather than ranking them.

The three guards built into every run

Leakage guard

The scaling constants are fitted on the training span only. Fitting them on the full series would leak the test range backwards into training and quietly inflate skill. Splits are chronological, never shuffled.

Size-matched baseline

An echo-state network is given exactly as many nodes as the reservoir has read-out features, so both models train the same number of weights. It is scored on the identical rows. When it wins, the run page says it won.

Measured coverage

Uncertainty bands are split-conformal, calibrated on a slice the read-out never saw. Realised coverage is then measured on the test split and shown next to the nominal level, because a band that misses its target is a broken forecast, not a tight one.

Reference lines you should look for

LineMeaning
NRMSE = 1.0 The mean predictor. At or above this, the model has learned nothing usable, whatever the other numbers say.
persistence Repeat the last observation. On a smooth series this is a strong forecaster, and beating the mean predictor while losing to persistence means the model adds nothing operationally.
ESN, size-matched The classical control at equal trained-parameter count. Parity with it is the defensible claim; losing to it is the common and expected outcome at these sizes.
rank(X) Hard upper bound on memory capacity. An MC touching it reports the size of the feature space, not the reservoir's dynamics.

Provenance tiers

TierWhat a result on it means
real record Observed data from a public archive. Out-of-sample skill here is a genuine result on a real record.
synthetic surrogate Generated for this project. Exercises the pipeline; carries no evidence about real-world performance.
simulated chaotic system Numerically integrated system with a known Lyapunov exponent. A controlled testbed, not an application result.

Memory capacity is measured separately, and on purpose

The diagnostics page drives the reservoir with an i.i.d. uniform stream rather than any dataset. Memory capacity is only defined for an i.i.d. drive: given an autocorrelated series, a memoryless read-out can infer past inputs from the present one, and the resulting number measures the smoothness of the data rather than the memory of the reservoir. Your real series have lag-1 autocorrelations around 0.95–0.99, so feeding them to that metric would produce a large and meaningless value.
