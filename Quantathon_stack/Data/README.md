# Data

Everything here is rebuilt by `python fetch_data.py`. Nothing is hand-edited, and
nothing large is vendored — the file is the recipe, the directory is its output.

```bash
python fetch_data.py            # real + surrogate + Lorenz-63
python fetch_data.py --dysts    # also integrate the chaotic systems (slow)
python fetch_data.py --force    # re-download and regenerate everything
python describe_real.py         # measure every file in real/
```

A first run takes a few minutes and needs network: the real tier downloads
~140 MB (most of it the OPSD file, which is subset down to 10 MB before it
touches disk). Everything is cached — an existing output file is never
re-fetched unless `--force` is passed. Total on disk: **27 MB**.

All sources are open and need no credentials. Two useful ones do require an
account and so are deliberately absent: **BSRN** (1-minute solar irradiance,
~80 stations — the highest-cadence real solar data available) and **OpenAQ**
(hourly PM2.5, free API key). Both are worth adding by hand if you need them.

Three tiers, in increasing order of how much you can trust a Lyapunov exponent
measured from them.

## `chaotic/` — ground truth, multiple realizations

The only tier where λ₁ is **known**, and the only tier with more than one
realization per system. Each `.npz` holds:

| key | meaning |
|---|---|
| `x` | `(R, N)` — R realizations of a scalar observable |
| `dt` | sample spacing, in the system's natural time units |
| `lyap` | published largest Lyapunov exponent |
| `ic_eps` | size of the initial-condition perturbation between realizations |

| file | system | λ₁ | R × N |
|---|---|---|---|
| `lorenz63.npz` | Lorenz-63 x-component | 0.9056 | 12 × 4000 |
| `vallieselnino.npz` | Vallis ENSO recharge oscillator | 0.5478 | 8 × 2500 |
| `lorenz84.npz` | atmospheric general circulation | 0.4615 | 8 × 2500 |
| `hadley.npz` | Hadley cell convection | 0.2387 | 8 × 2500 |
| `rikitakedynamo.npz` | geomagnetic reversal dynamo | 0.1318 | 8 × 2500 |

`AtmosphericRegime` (λ₁ = 0.0105) is also available via
`--only AtmosphericRegime`, but is not included: its period is ~90 natural time
units, so integrating enough realizations takes far longer than the others, and
at λ₁ ≈ 0.01 it is barely chaotic — a poor test case for an estimator.

Everything past `lorenz63.npz` comes from [dysts](https://github.com/williamgilpin/dysts)
(135 annotated chaotic systems) and needs `pip install dysts numba`. **Install
numba** — without it dysts falls back to pure Python and integration is roughly
10× slower. The systems above are the climate- and geophysics-relevant subset;
`Lorenz96` is also available via `--only Lorenz96` but is 4-D and much slower.

Realizations are generated by perturbing the initial condition *after* burn-in,
so every member starts on the attractor separated by a known `ic_eps`. That is
what makes them a usable ensemble: pairwise divergence measures λ₁ directly,
with no delay embedding involved.

### `tao_daily_sst.csv` — TAO/TRITON moored buoys

Daily SST at five equatorial Pacific moorings (0°N at 165°E, 170°W, 155°W,
140°W, 110°W), wide format, one column per site on a gapless daily index.
Values 17.35–31.32 °C; per-site standard deviation rises from 0.79 °C in the
warm pool (165°E) to 2.21 °C in the cold tongue (110°W), which is the ENSO
signal itself getting stronger eastward.

This is the most useful real file here: **daily** cadence in the ENSO region,
where everything else you have is monthly. It is also the closest thing to
multiple realizations available in real observations — but the moorings are
dynamically coupled along the equator, so inter-site spread is a *lower bound*
on true ensemble spread, not an initial-condition ensemble.

**Caveat: 25–39% missing per site, longest gap 1,135–4,153 consecutive days.**
The array degraded badly around 2012–2014 for funding reasons. `analyse()` will
warn and interpolate; at these gap lengths that means the interpolator, not the
ocean, is being measured. Work on contiguous sub-spans instead.

### `ghcnd_*.csv` — GHCN-Daily station records

Daily maximum/minimum temperature (°C) and precipitation (mm) from single
stations, parsed out of NCEI's fixed-width `.dly` format with the −9999
missing-value code applied and tenths scaled to natural units.

Central Park is the longest record in this folder at any cadence — **157.5
years, 57,540 daily observations, effectively complete** (7 missing values in
each temperature column). That combination of length, cadence and completeness
makes it the best-conditioned real series available for a Lyapunov estimate,
even though its dynamics are mid-latitude weather rather than climate.

Los Angeles is included as a contrasting regime: same variables, much weaker
seasonal cycle, 82 years.

### `usgs_potomac_*.csv` — river discharge, Potomac at Little Falls

Streamflow in cubic feet per second at USGS gauge 01646500. Two files from one
gauge at two cadences: 96 years of **daily** values, and 5 years of
**15-minute** values (the instantaneous service does not serve long spans).

The 15-minute file is the highest-cadence real series here — 239,261 readings.
Note its timestamps are **not** perfectly regular: 43.8% of steps differ from
the 15-minute median, with occasional multi-hour intervals. Resample onto a
fixed grid before embedding rather than assuming uniform Δt.

Discharge is strongly heavy-tailed (121 to 426,000 cfs daily), so consider a log
transform before any variance-based analysis. SDG 6 (clean water).

### `opsd_hourly_load.csv` — European electricity demand

Hourly actual load in MW for 25 countries, from ENTSO-E via Open Power System
Data. This is the real counterpart to `surrogate/system_load.csv`, and the
comparison is the point: the surrogate's diurnal-plus-weekly structure can be
checked against genuine demand.

Only whole-country columns with under 1% missing are kept — bidding-zone
subdivisions (`DE_50hertz`, `NO_1`, …) are dropped because they are components
of a country already present. The published file is ~130 MB of every variable;
this is ~8% of it. Span is limited to 2014-12 → 2020-09 by the upstream release.

### `nino34_anom.csv` / `enso_nino12_1950_2010.csv` — ENSO indices

`nino34_anom.csv` is the better of the two: 25% longer, current to last month,
and the actual Niño 3.4 region rather than the Niño-1+2-type proxy (whose
variance phase-locks to May rather than DJF — a limitation the existing
walkthrough already flags). Already an *anomaly*, so the annual cycle has been
removed upstream by subtracting a monthly climatology.

`enso_nino12_1950_2010.csv` is absolute SST, not an anomaly, and is kept so
results stay comparable with the published pipeline. **The two are not directly
comparable** without deseasonalising the second.

Both are short in sample count — 918 and 732 points. At monthly cadence a
Lyapunov estimate has very few samples per Lyapunov time, which is the main
reason the ENSO λ₁ figures elsewhere in this project are unreliable.

### `psmsl_*_monthly_sealevel.csv` — tide-gauge sea level

Monthly mean sea level in mm on the Revised Local Reference datum, from the
Permanent Service for Mean Sea Level. Brest reaches back to **1807** — the
longest span in the folder by a wide margin — but is 11.9% missing with a
120-month gap. Cuxhaven is shorter (1854) and far more complete (0.44%).

Monthly cadence and a strong secular trend (sea-level rise) mean these need
detrending before any dynamical analysis. Best used as a slow-variable contrast
to the daily series. SDG 13/14.

### A note on "real"

All of these are *observations*, but none are raw instrument output. The ENSO
indices are gridded reanalyses blending ship, buoy and satellite data through a
statistical model; GHCN-Daily is quality-controlled and homogenised; PSMSL is
datum-adjusted. Real, but processed — and each processing step is a modelling
choice made upstream of you.

## `surrogate/` — synthetic, physically motivated

| file | what |
|---|---|
| `solar_ghi.csv` | 30-min GHI, one year, lat 1.35 N; Haurwitz clear-sky × two-state Markov cloud, with sensor-outage gaps injected |
| `system_load.csv` | hourly system load, three years; weekly/diurnal profile × annual seasonality + CDD/HDD response + AR(1) residual |

Generated from `QRC_code_stack/stage1_numpy_core/datasets.py` at its fixed
seeds, so they are reproducible but **not observations**. Useful for pipeline
work; not evidence about real climate dynamics.

## Why the chaotic tier exists

A Lyapunov exponent estimated from a single finite record is a *fit*, and fits
need a control. This tier is the control — the only data here where λ₁ is
known in advance. Measured with `DataBase_Analysis/lyapunov.py`:

| system | truth | ensemble | error | Rosenstein (mean over members) | error |
|---|---|---|---|---|---|
| Lorenz-63 | 0.9056 | 0.8231 | −9% | 2.3130 | +155% |
| Vallis–El Niño | 0.5478 | 0.5200 | −5% | 1.3013 | +138% |
| Lorenz84 | 0.4615 | 0.7499 | +63% | 0.7003 | +52% |
| Hadley | 0.2387 | 0.3759 | +58% | 0.1643 | −31% |
| RikitakeDynamo | 0.1318 | 0.1049 | −20% | 0.2494 | +89% |
| | | **mean 31%** | | | **mean 93%** |

**Read this table before trusting any λ₁ in this project.** Three conclusions,
and they are not the same conclusion:

1. **Rosenstein on a single trajectory is unusable as a measurement.** Mean
   absolute error 93%, and the sign is not even consistent — four systems
   overshoot, one undershoots. It substitutes spatial neighbours *within one
   trajectory* for genuinely independent perturbations, so it inherits every
   delay-embedding artefact. Its per-member scatter is only a few percent,
   which means the wrong answers are *reproducible* wrong answers: consistency
   across members is not evidence of accuracy.

2. **The ensemble estimator is much better but is not a precision
   instrument.** Errors run −20% to +63%, mean 31%. Right tool when
   realizations exist, but "T_λ = 1.92" should be read as "order 2", never as
   three significant figures. The error is dominated by where the scaling
   region is placed, not by the divergence curve: on one fixed Lorenz-63 curve,
   four hand-picked windows give 0.71, 0.82, 1.01 and 1.46.

3. **Neither works on an observed record, and the reason is noise, not
   length.** Degrading Vallis–El Niño to Niño 3.4's conditions: at 918 samples
   with a clean ensemble the estimator still returns −11%, but adding **1%**
   observational noise takes it to −94%, and **2%** makes it unmeasurable. The
   exponential phase lives at separations between `ic_eps` and the attractor
   diameter; noise puts a floor under separation and buries it. Real SST has
   considerably more than 2% observational uncertainty. This is an information
   limit — no record length and no number of members recovers it.

Consequently **no λ₁ is quoted for any observed record in this project**. The
estimator enforces this itself: a `MIN_RISE_NATS = 3` guard reports *not
measurable* unless the divergence curve actually climbs. Chaotic tier: 10.4 to
16.5 nats. White noise: 1.0. Every observed record here: 0.8 to 2.0.

The `lyap` and `ic_eps` values stored in these `.npz` files are **asserted, not
measured** — written in by `fetch_data.py` from published values. Lorenz-63's
0.9056 has been verified independently (Benettin tangent-space integration at
the generator's own step size gives 0.9080, +0.3%, and the stored `ic_eps`
matches the data's actual initial separation). **The four dysts systems have
not been verified this way.** Lorenz84 and Hadley carry the two largest
ensemble errors, and whether that is the estimator or stale metadata is open.

See `DataBase_Analysis/analysis.md` for the full evidence and for what to
measure instead; `test_lyapunov.py` for the anchors that keep it honest.


## Not vendored (too large — fetch directly)

For real data with **multiple realizations**, the concept is an
*initial-condition large ensemble*:

- [CESM2-LENS2](https://www.cesm.ucar.edu/community-projects/lens2) — 100 members, 1850–2100, 1°; also on [AWS S3 as Zarr](https://registry.opendata.aws/ncar-cesm2-lens/)
- [ERA5 EDA](https://confluence.ecmwf.int/display/CKB/ERA5:+uncertainty+estimation) — 10 perturbed reanalysis members, 3-hourly, via the [Copernicus CDS](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels)
- [WeatherBench 2](https://sites.research.google/gr/weatherbench/) — ERA5 ground truth plus IFS ENS ensemble baselines on GCS

Needs an account, so it cannot go in `fetch_data.py`:

- [BSRN](https://bsrn.awi.de/) — **1-minute** solar irradiance, ~80 stations, 1992–; via the [PANGAEA portal](https://dataportals.pangaea.de/bsrn/). Highest-cadence real solar data there is, and the proper counterpart to `surrogate/solar_ghi.csv`
- [OpenAQ](https://docs.openaq.org/) — hourly PM2.5/NO₂/O₃ from physical monitors worldwide (SDG 3, 11); free API key

Broader, if the scope widens:

- [CAMELS](https://ral.ucar.edu/solutions/products/camels) — 671 catchments with attributes, vs. the single gauge vendored here (SDG 6)
- [GHCN-Daily bulk](https://www.ncei.noaa.gov/products/land-based-station/global-historical-climatology-network-daily) — 100,000+ stations; two are vendored, the archive is a compressed tarball of all of them
- [NOAA ISD / GHCNh](https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly) — hourly station wind, temperature, pressure, 35,000 stations
- [UN SDG Indicators database](https://unstats.un.org/sdgs/dataportal/database) — SDMX API (annual, country-level; too coarse for dynamics)
